# M6 supported scope and limits

The release decision and exact verified implementation are recorded in [M6_REPORT.md](../M6_REPORT.md). File analysis does not certify physical strength or printer-specific fit.

- A browser STL audit accepts at most 2,000,000 triangles per file. ZIP and combined batch collections are limited to 256 MiB; ZIP64 and unlimited workloads are not supported. Lower processing or hardware detail when a budget is exceeded.
- Browser batches accept at most 20 images, 128 MiB combined input and 64 MiB per image. A saved batch recipe is limited to 100 MiB. Image/variation combinations are limited to 128 jobs. Jobs run sequentially with fresh inspection and validation workers. Completed results can be collected after cancellation; processing requires the application or tab to remain open.
- Folder selection uses the browser's directory picker where available. Other browsers use multiple-file selection. The application cannot spawn a CLI process, discover arbitrary folders or write unattended into arbitrary output directories. Downloads use the browser's normal save behavior. The native CLI retains its own folder, batch and sweep commands.
- A batch replaces the selected source operation with a fresh image identity. Other sources and unused original attachments are preserved. Missing originals cannot be reconstructed; a replacement can supply the intended source. Unsupported imported operations or namespaces remain preserved and must be resolved before execution.
- Unknown project content is retained. An unknown operation is not advertised as executable. History is a bounded session history of 100 retained edits; browser reload starts a new undo session. Saved project values, IDs, connections, metadata, style banks and originals persist.
- Persistent browser storage depends on browser permissions and quota. Processing and explicit project downloads work with unavailable/full storage, using a bounded 128 MiB session image cache. Saving the downloaded project is necessary for persistence in that situation. A damaged autosave remains downloadable for recovery.
- Colour splitting supports ten masks. A registration operation supports six solid plates; seven to ten layers use separate groups. Cross-group alignment requires matching dimensions and hole settings. Pins intentionally contain the requested number of disconnected pin bodies; fragment retention intentionally permits its selected number of stencil bodies.
- Mesh optimization operates on solids before splitting, rather than arbitrary hardware or Parts collections. Tile-first generation does not expose the post-solid seam bevel parameter. Physically impossible connector/pad clearances produce explicit constraints instead of manufacturing files. Turning off tile-island bridging can leave disconnected material; ordinary and batch export block such a tile until bridging is restored.
- Traced SVG is an artwork outline before physical bridge correction. A bridge-corrected manufacturing SVG, arbitrary vector-point editor, generic bridge-off switch, image/text composition and G-code were absent upstream and are not added in M6.
- Native, single-thread and multithread outputs may use different valid triangulations. The retained comparisons distinguish structural validity, exact surfaces, certified small numerical surface differences, exact triangles and file bytes. The measured corpus does not prove every possible input combination.
- Physical printing, printer-specific fit, fresh-machine installation, installers and Windows/macOS/Linux distribution qualification remain M7 work. This Windows session exercises Chromium; Firefox, Safari and other platform browser behavior are not certified here. Linux source/browser verification is recorded separately from Windows local results.
- GitHub Pages is an explicit optional deployment. M6 does not enable public hosting or change repository visibility.

M7 must be authorized separately. M6 does not begin packaging, platform installation or physical-print certification work.
